TrustRAG

An offline question-answering system that checks every sentence of its own answer against the documents it retrieved, and blocks what the evidence does not support.

Offline, open-weight models only: Sentence-BERT and FAISS for retrieval, TinyLlama for generation, and a DeBERTa NLI model with BERTScore and cosine similarity for verification. Thesis: TrustRAG, a trustworthy offline retrieval-augmented generation framework with explainable multi-signal hallucination detection, and TrustRAG-Opt, a controlled comparison of retrieval indexes.

Problem and objectives

Retrieval does not guarantee a faithful answer

Retrieval-augmented generation hands a language model relevant documents before it answers. The model can still ignore or misread them and write sentences the documents never supported. Most detectors depend on external fact-checking, heavy classifiers or cloud APIs, and they rarely show which piece of evidence is supposed to back which statement.

Given a query, a set of chunks and a generated answer, TrustRAG decides for every sentence whether the retrieved evidence supports it, and then whether the whole response is fit to show. It does this with local models only, traces each decision to a specific chunk, and returns a calibrated score instead of a flat yes or no.

Research gap

Retrieval quality, factual-consistency checking and explainability are usually studied separately. Few systems give a sentence-level score tied to evidence that works fully offline.

Second question

Does the choice of retrieval index change what gets verified, and does it matter for response time once verification is the expensive part? That is TrustRAG-Opt.

Three SDGs

SDG 9 (offline infrastructure), SDG 16 (accountable AI that suppresses unsupported claims) and SDG 4 (answers that are safer to learn from).

Objectives

1. Build an offline RAG framework for evidence-grounded responses.

2. Implement semantic retrieval with Sentence-BERT and FAISS.

3. Add sentence-level evidence attribution and a provenance score.

4. Detect hallucination with NLI, BERTScore and cosine similarity.

5. Fuse the signals into a Trust Score and a tri-state decision.

6. Evaluate on a labelled benchmark and an external one, and report where it fails.

7. Compare four retrieval back-ends under the fixed verifier, with repeated runs.

Which retrieval index should sit in front of the verifier?

Where the time goes. Index choice moves search time by thousandths of a millisecond. The NLI check that verifies each answer takes about 0.6 seconds.

Search (FlatIP)0.0054 ms
NLI verification605 ms

On this collection, choosing an index is a quality and memory decision, not a way to cut end-to-end latency. Only HNSW with efSearch 16 is faster than exact search (1.15 times), and the size of the collection matters: at a few hundred vectors the usual speedups of approximate indexes do not appear.

    Limitations stated in the thesis
    • Scale. One 213-chunk collection and one embedding model. Orderings at a few hundred vectors do not establish orderings at thousands or millions.
    • Labels. One annotator wrote and labelled the 109 claims. There is no agreement statistic.
    • Development set. The project set was used to inspect the detector. RAGTruth is the external estimate.
    • Generation. Generation was not run during the repeated index measurements.
    • Baseline. A full conventional-RAG run has not been executed. A narrower comparison against a pass-through that accepts every claim is in the results above.
    • No superiority claim. Cited systems were not re-run on these splits.
    Phase II plan
    1. Calibrated verifier. Fine-tune a faithfulness classifier on the RAGTruth training portion, freeze it, then evaluate the test split once.
    2. Conventional-RAG baseline. One controlled run on the same 37 questions with the verification layer on and off, reported as an end-to-end hallucination rate.
    3. Scale. Grow the corpus in stages with the same index hyperparameters, repeat the timing protocol, and add a second embedding model.
    4. Annotation. A second annotator and an agreement score.
    5. Adaptive control. Per-domain weights and thresholds, multi-hop evidence, multilingual retrieval, and a faster cross-encoder.
    Organizational customization
    An organization drops its approved PDF, DOCX, TXT and Markdown files into the corpus folder and rebuilds the index. Answers are then drawn from and checked against that index. Retrieval can still miss evidence and sources can be wrong, so the organization's own questions should be labelled and the evaluation repeated whenever the corpus changes.
